local failure

	Most errors are timing errors (something unforeseen)
		What is the cost of a back up system?
		What is the cost of a failure
	Tandem was terrible: two copies of everything to restart and synchronize



a global failure
	if a disk fails, only recover the disk
	usual answer: recover the database as fast as possible
		takes far too long
	If you have a 50,000 files (terminals) and it takes a second to open (can't be done in parallel) -- 12 hours
	With XRF, the right answer was to have another, backup system "ready to take over"
		A shared database between the primary and backup system
		The primary system had exclusive locks on everything
		The backup system could only listen but could read the journal and was aware of all of the locks
	The backup system looked at the changes and copied the system
	Backup system consumed less than 5% of the resources	

On a crash
	The backup system took over
	The primary system now could only wash
	The backup system had the entire control structure and file system (terminals)
	No database recovery -- the backup merely took over updates in the shared data
	The backup needed to recover only currently locked rows
		Immediate recovery of any records in conflict (records that were in the process at the time of failure)
		Recovery of the rest could happen in background
	20 seconds to system full operating, invisible to user/clients/operator

**Messaging**
	Terminal sent a numbered message that the system didn't receive because it was dying
	On recovery, the terminal was already open, sent a short verify message with last message received
		Got back either "Here are the messages I've sent you haven't received" or 
		"These are the messages you sent that I missed" or
		"We're on the same page"
