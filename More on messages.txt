While we have microservices
	We need to see all the messages between all the services to (for example) determine why a process is "stuck"
	A central store for all messages? A separate machine that all messages go through? (single point of failure)

The message number is really just the count of the messages in this conversation
	Each partner needed to keep track of the last message received
		Can request any message not received
		Ignore any "re-sent" message already committed (marked as recoverable)
	Each partner needs a copy of each message sent not yet acknowledged as committed (marked as recoverable) by the partner
		Keeping "too many" messages not a problem -- the partner will ignore "re-sent" messages
		Not keep "enough" message so can't re-send if requested
		Simplest solution: keep every message in a conversation and discard only when conversation is over

Even if, in the event of a failure, during recovery a transaction is discarded
	The crashing partner will send a "didn't process" process to other partner
	The other partner can re-submit the message(s) to finish the transaction
		Invisible to the user

But we need to recognize that there may need to be a correction
	Which needs the ability to forward chain -- which a journal doesn't include

Each message has a deadline and the time series can be ordered by the deadline
