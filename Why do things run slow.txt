Time series
	Take the journal
	Convert into a time series (a materialized view) with critical data
		A highly compressed journal
	Anything that does go into the time series, goes off to the side to be written out later
	Need to wait until the time series is complete
		For example, the application could abort the process
	When the application commits -- the time series is ready to be written
		No more data to come		

Why does performance not degrade as the number of transactions increases
As the number of transactions increases all that happens is 
	The number of unavailable buffers increases
	The number of requests passed to the scheduler increases
	As the number of transactions increase all that happens is the number of separate writes decreases
		Instead, we write larger blocks continuously
